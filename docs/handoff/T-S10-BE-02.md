# Handoff Document: T-S10-BE-02 - Moderation Pipeline, Sanctions & Audit Batched

## Overview
Implemented the full moderation pipeline, sanctions lifecycle, and immutable audit logging system across the new Moderation module (`BrainMemo.Moderation.*`), integrating synchronous cross-module enforcement (Identity, Course, Learning) and asynchronous domain events.

## Implemented Components
1. **Moderation Module Architecture**:
   - `BrainMemo.Moderation.Contracts`: Domain enums (`ReportSource`, `ReportTargetType`, `ReportStatus`, `EvidenceKind`, `SanctionType`, `SanctionTargetType`, `LiftKind`, `AuditActorType`, `AuditAction`, `AuditObjectType`), integration events (`ReportResolved`, `SanctionApplied`), and contract interface `IModerationContract` with `SubmitAiFlag`.
   - `BrainMemo.Moderation.Domain`: Core entities `Report`, `ReportEvidence`, `Sanction`, and `AuditLog`.
   - `BrainMemo.Moderation.Application`:
     - Queries: `ListReportsQuery`, `GetReportByIdQuery`, `GetReportTargetContentQuery` (DEC-02 `AccessPurpose.ModerationReview`), `ListSanctionsQuery`, `ListAuditLogsQuery`, `GetModerationDashboardQuery`, `ListCourseReportsQuery`.
     - Commands: `CreateReportCommand` (duplicate prevention, evidence handling), `ResolveReportCommand` (atomic single-transaction resolution orchestrating sanctions and external contract invocations), `ApplySanctionCommand` (direct administrative sanctions), `LiftSanctionCommand` (manual restoration and account unlocking).
   - `BrainMemo.Moderation.Infrastructure`:
     - `ModerationDbContext` with EF configurations for `mod_report`, `mod_report_evidence`, `mod_sanction`, and `mod_audit_log` (big-endian GUID conversion).
     - `ModerationTransaction` supporting relational transactions with `IAmbientTransactionAccessor.Push` and in-memory test mode.
     - `ModerationContractService` implementing `IModerationContract.SubmitAiFlag` idempotently.
     - `RestoreExpiredHiddenCoursesWorker` auto-restoring courses whose temporary hide duration expired.
     - `AccountUnlockedEventHandler` lifting temporary account lock sanctions when `AccountUnlocked` event is received.
   - `BrainMemo.Moderation.Api`:
     - `ReportsController`: `POST /api/v1/reports`, `GET /api/v1/courses/{courseId}/reports`.
     - `AdminModerationController`: `GET /api/v1/admin/reports`, `GET /api/v1/admin/reports/{id}`, `GET /api/v1/admin/reports/{id}/target-content`, `POST /api/v1/admin/reports/{id}/resolve`, `POST /api/v1/admin/sanctions`, `GET /api/v1/admin/sanctions`, `POST /api/v1/admin/sanctions/{id}/lift`, `GET /api/v1/admin/audit-logs`, `GET /api/v1/admin/dashboard`.
2. **Atomic Resolution & ADR-03 Invariants**:
   - Single-transaction orchestrator checks report is `PENDING`, persists sanctions, applies cross-module contract calls (`Identity.LockAccount`, `Course.HideCourse`, `Learning.SoftDeleteComment`, `Course.PermanentlyDeleteCourse`), appends immutable audit records, and commits transaction before publishing events. If any step fails, the entire transaction is rolled back with zero partial effects.
3. **Target Content Preview (DEC-02)**:
   - When inspecting report target content via `GET /api/v1/admin/reports/{id}/target-content`, moderation verifies course access mode with `AccessPurpose.ModerationReview`. If the course has `ONLY_ME` visibility, a 404 Not Found is returned.
